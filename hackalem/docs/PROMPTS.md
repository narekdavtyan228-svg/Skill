## 1. Кикофф — Роль A (Ядро и контракт)

```
Ты работаешь в роли A (Ядро и контракт) на 5-часовом хакатоне. Прочитай AGENTS.md целиком — это контракт, он важнее твоих привычек.

Твои каталоги: core/, eval/, Makefile, requirements.txt, .codex/. В data/, extract/, rules/, ui/ не пишешь ничего.

Задача первого среза (45 минут): сквозной каркас, который запускается и печатает валидный JSON на одном тестовом комплекте, пусть даже вся начинка — заглушки.

1. core/schemas.py — Pydantic v2 модели ровно по разделу 3 AGENTS.md: PermitResult, Finding, Prooflink, Validation. Строгая валидация: пустой список prooflinks у finding со статусом confirmed = ошибка валидации.
2. core/mock_api.py — четыре функции с фиксированными детерминированными ответами: employee_clearance(employee_id), gas_test_status(permit_id), asset_isolation(asset_id), site_restrictions(zone_id). Каждая возвращает и данные, и источник (source_id + location) для prooflink. Если организатор выдал свой SDK — оберни его здесь адаптером, не вызывай напрямую из других слоёв.
3. core/orchestrator.py — функция run(permit_dir) -> PermitResult: извлечение (импорт из extract/, пока заглушка) → вызовы mock_api → правила (импорт из rules/, пока заглушка) → сборка результата.
4. eval/run.py — читает data/ground_truth.json, гоняет orchestrator по всем комплектам, печатает: recall по нарушениям, число ложных approve, долю findings без валидного prooflink.
5. Makefile: цель smoke (один комплект end-to-end), цель eval, цель ui.
6. requirements.txt, .env.example, .gitignore (.env, .venv, __pycache__).

Интерфейсы для B и C зафиксируй явными сигнатурами функций и допиши их в docs/requests/a.md, чтобы они не гадали.

Используй $contract-first и $python-patterns. Сначала напиши план в docs/plan-a.md и остановись.
```

## 2. Кикофф — Роль B (Данные и извлечение)

```
Ты работаешь в роли B (Данные и извлечение) на 5-часовом хакатоне. Прочитай AGENTS.md целиком.

Твои каталоги: data/ и extract/. В core/, rules/, ui/ не пишешь ничего — интерфейсы берёшь из core/schemas.py и docs/requests/a.md как есть.

Задача первого среза (45 минут):
1. data/generator.py — генератор синтетических комплектов наряда-допуска. Комплект = папка data/fixtures/permit_XXXX/ с: наряд (PDF, генерируй через reportlab или fpdf2, с реальным текстом — сканы имитируем позже), карточка работника (JSON), выписка журнала газоанализа (CSV), перечень изоляций (CSV).
2. Всего 60 комплектов, в 20 из них зашиты контролируемые нарушения из ТЗ: просроченный газоанализ, отсутствующая подпись, неверная зона, несовместимые одновременные работы, просроченный допуск работника, неподтверждённая LOTO-изоляция.
3. data/ground_truth.json — для каждого комплекта: список нарушений с rule_id и точным местом (файл + страница/строка). Это эталон для eval, он важнее красоты генератора.
4. Сначала сделай 10 комплектов и убедись, что eval роли A их читает. Потом доливай до 60.
5. extract/extractor.py — извлечение полей из комплекта в строгую схему через OpenAI structured outputs. Каждое извлечённое поле обязано нести источник: имя файла + страница/строка + цитата. Поле, которого нет в документе, возвращается как None со статусом insufficient_evidence — не придумывай.

Правило разбора: начни с детерминированного парсинга (regex/pdf-текст), LLM подключай только там, где детерминизм не справился. См. $regex-vs-llm-structured-text.

Перед работой с PDF прочитай .agents/skills/anydoc/SKILL.md. Сначала напиши план в docs/plan-b.md и остановись.

## 3. Кикофф — Роль C (Правила и витрина)

```
Ты работаешь в роли C (Правила и витрина) на 5-часовом хакатоне. Прочитай AGENTS.md целиком.

Твои каталоги: rules/, ui/, docs/pitch/. В core/, data/, extract/ не пишешь ничего.

Задача первого среза (45 минут):
1. rules/matrix.yaml — матрица допуска, 8 правил с полями: rule_id, описание на русском, severity (P1/P2/P3), условие, какие источники нужны, какое решение человека требуется при срабатывании. Минимум: срок действия газоанализа, действующий допуск работника, подпись ответственного, соответствие зоны работ, подтверждённая LOTO-изоляция, конфликт одновременных работ, соответствие времени работ смене, комплектность пакета.
2. rules/engine.py — исполнение правил детерминированно в Python. Никакой арифметики «на глаз»: сроки и интервалы считаются кодом. Каждое сработавшее правило возвращает Finding по схеме из core/schemas.py, включая prooflinks из входных данных.
3. rules/verdict.py — агрегация в вердикт: любое P1 → block_and_escalate; отсутствие обязательного источника → block_and_escalate с классификацией insufficient_evidence (НЕ approve); только P3 → approve_with_conditions. Ветки approve без полного набора подтверждений не существует.
4. ui/app.py — Streamlit: выбор комплекта, кнопка «Проверить перед началом работ», результат — крупная красная карточка «РАБОТЫ НЕ НАЧИНАТЬ» со списком барьеров; у каждого барьера раскрывается источник (файл, страница, цитата) и строка «требуется решение: …». Замеченный unknown показывается отдельным серым блоком, не прячется.
5. ui/replay/ — режим демо: один клик проигрывает заранее выбранный ловушечный комплект.

До готовности core/ работай на фиктивном JSON, соответствующем схеме, чтобы не блокироваться.

Перед версткой прочитай .agents/skills/ui-ux-pro-max/SKILL.md. Сначала напиши план в docs/plan-c.md и остановись.
```

## 4. Управляющие фразы (короткие, по одной)

| Ситуация | Фраза |
|---|---|
| План принят | `одобрено, выполняй` |
| План лезет не туда | `план выходит за границы моей роли по AGENTS.md §5. Перепиши, оставаясь в своих каталогах.` |
| Начал «упрощать» требования | `стоп. Раздел 2 AGENTS.md не опционален. Верни fail-closed логику и prooflinks, тесты подгоняй под требование, а не требование под тесты.` |
| Сказал «готово» без проверки | `покажи вывод make smoke, python -m eval.run и pytest -q. Без них задача не закрыта.` |
| Закрытие цикла | `$verification-loop, затем коммит и пуш по правилам AGENTS.md §6` |
| Пора сохраниться | `git pull --rebase, добавь только свои каталоги, коммит с префиксом [X], пуш` |
| Контекст переполнен | `$strategic-compact` (а лучше — закрыть сессию и открыть новую) |

## 6. Питч и демо (роль C, T+210)

**Слайды:**

```
$frontend-slides
Собери 6 слайдов на 3-минутный питч, по-русски, без воды:
1. Боль: проверка одного наряда-допуска вручную 10–25 минут, цена пропущенного барьера — жизнь; владелец процесса — директор по промбезопасности.
2. Что показываем: пакет документов → кнопка → красная карточка «Работы не начинать» с двумя барьерами и ссылками на источник.
3. Архитектура одной схемой: извлечение → mock-реестры → детерминированные правила → вердикт с prooflinks → HITL.
4. Почему это не чат-бот: fail-closed, честный unknown, арифметика кодом, ноль ложных approve на автотесте.
5. Цифры автотеста: recall по 20 нарушениям, ложные approve = 0.
6. Траектория A → B → C: пилот на обезличенной выгрузке за 4–8 недель, далее внутрь периметра через механизм 1% на НИОКР. Адресаты: ТШО, KPO, Qarmet.
Тон деловой, шрифт крупный, читается с проектора из дальнего ряда.
```

```
Прочитай .agents/skills/diagram-design/SKILL.md и нарисуй схему потока данных PermitGuard для слайда 3: источники документов, агент извлечения, четыре mock-реестра, движок правил, верификатор prooflinks, HITL-выход. Подписи по-русски, максимум 12 блоков.
