# HackAlem · Трек «Добывающая промышленность» — рабочий репозиторий команды

Скелет проекта со всей обвязкой: контракт для агентов, конфигурация Codex с ECC, промпты трёх ролей, скрипты установки и часовая отчётность. Кода задачи здесь нет намеренно — его пишут агенты, каждый в своём каталоге.

**Задача по умолчанию:** № 2 PermitGuard — предсменный инспектор наряда-допуска. Замена на другую — `docs/setup/RUNBOOK-3-MACHINES.md`, Приложение Б.

---

## Что где лежит

| Путь | Что это | Владелец |
|---|---|---|
| `AGENTS.md` | **Главный файл.** Codex читает его в начале каждой сессии: миссия, жёсткие правила, контракт результата, карта владения файлами, git-протокол, определение готовности | A |
| `.codex/config.toml` | Профили Codex. `hack` — работа без запросов подтверждения, `safe` — только чтение | A |
| `checkpoint.sh` | Часовая отчётность: где вы по таймлайну, кто что закоммитил, зелёные ли ворота приёмки | A |
| `Makefile` | `smoke`, `eval`, `test`, `data`, `ui`, `status` — единый способ проверить, что сделано | A |
| `docs/PROMPTS.md` | Кикофф-промпты трёх ролей, управляющие фразы, аварийные и питч-промпты | общий |
| `docs/setup/` | Регламенты и скрипты установки (см. ниже) | A |
| `docs/requests/{a,b,c}.md` | Запросы между ролями. Нужна правка в чужом каталоге — строка сюда, а не молчаливое редактирование | каждый свой |
| `docs/status/` | Автоотчёты чекпоинтов, копятся сами | A |
| `.agents/skills/` | Вендоренные внешние скиллы (ui-ux-pro-max, diagram-design, anydoc) | A |
| `core/`, `eval/` | ядро, контракт, mock-API, оркестратор, метрики | A |
| `data/`, `extract/` | генератор синтетики, эталон, извлечение полей | B |
| `rules/`, `ui/`, `docs/pitch/` | движок правил, вердикт, витрина, слайды | C |

Разделение каталогов — не формальность: на нём держится параллельная работа трёх агентов без конфликтов в git.

## Выберите свою схему

| Схема | Регламент | Скрипт установки |
|---|---|---|
| **Три машины**, у каждого свой Codex и свой GitLab | `docs/setup/RUNBOOK-3-MACHINES.md` | `docs/setup/setup-machine.sh` |
| **Одна машина**, три аккаунта Codex и три GitLab на ней | `docs/setup/RUNBOOK-1-MACHINE.md` | `docs/setup/setup-solo.sh` + `docs/setup/lane.sh` |

Для варианта с одной машиной корневой `AGENTS.md` заменяется на версию с дорожками:

```bash
cp docs/setup/AGENTS-1-MACHINE.md AGENTS.md
```

Различия только в §6 (три рабочих копии и remote-алиасы GitLab) и §11 (порты, общее железо).

## Первые шаги

**Накануне хакатона** (60–80 минут, не откладывать на площадку — Wi-Fi на 500 команд не выдержит установки):

1. Роль A создаёт приватный проект в GitLab, добавляет двоих как Maintainer, снимает защиту с `main`, пушит этот скелет.
2. Каждый ставит ECC и окружение своим скриптом из `docs/setup/`.
3. Все трое прогоняют репетицию на 45 минут: три сессии Codex одновременно, каждый пушит в `main`, `make smoke` зелёный.

**В момент старта:**

```bash
git pull --rebase origin main
source ~/.venvs/hack/bin/activate
./checkpoint.sh start
git add .hack-t0 && git commit -m "[A] ops: T+0" && git push     # отсчёт общий для всех
```

Роль A вписывает блок задачи в `AGENTS.md`, пушит, остальные делают `git pull`. Дальше каждый:

```bash
codex -p hack
```

и вставляет свой кикофф-промпт из `docs/PROMPTS.md`. Агент пишет план в `docs/plan-<буква>.md` и останавливается — вы читаете его 60 секунд и отвечаете `одобрено, выполняй`.

---

## Три правила, которые решают исход

1. **Контракт до кода.** Всё, что агент должен знать, живёт в `AGENTS.md`, а не в чате. Тогда любая новая сессия у любого из троих стартует с полным контекстом, и перезапуск застрявшего агента стоит десять секунд.
2. **Машинная приёмка.** «Готово» — это зелёные `make smoke`, `make eval`, `make test`, а не фраза агента. Поэтому Makefile должен работать уже на заглушках, с первого часа.
3. **Контракт замораживается на T+45.** После этого `core/schemas.py` меняет только роль A. Три слоя, которые встретились впервые на третьем часу, не сойдутся никогда.

## Отчётность

```bash
./checkpoint.sh --loop 60 --commit    # роль A, висит в отдельном терминале до конца
./checkpoint.sh --quick               # остальные, когда нужен быстрый взгляд
```

Каждый срез показывает: сколько прошло и осталось, **в какой фазе таймлайна вы должны быть** (не где вы есть), активность в git за час по авторам и каталогам, состояние трёх ворот приёмки с первыми строками ошибок, размер датасета, открытые запросы между ролями и чек-лист критериев жюри. Отчёты ложатся в `docs/status/`.
